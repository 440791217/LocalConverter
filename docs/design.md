# LocalConverter 采集服务设计

更新日期：2026-10-18  
状态：单路采集原型已完成。当前实现 RTSP 接入、WebRTC 本机预览、JPEG 截图、共享连接、会话心跳、超时释放、基本并发限制和媒体子进程回收。正式业务授权、配置变更通知及现有标注页面接入尚未实现；实际接口见 api.md。

## 1. 目标与边界

LocalConverter 运行在工位电脑上，连接该电脑能够访问的 RTSP 摄像头，为浏览器提供预览和截图。一个服务管理多个摄像头，启动时无需预先知道设备数量。

| 组件 | 职责 |
| --- | --- |
| Java 业务后台 | 用户权限、工位和设备配置、RTSP 地址及配置版本、图片和标注存储 |
| LocalConverter | 按需连接摄像头、共享采集连接、管理会话、预览、截图、超时释放和断线重连 |
| 浏览器 | 获取设备配置、选择摄像头、维持使用会话、展示画面、拍照标注、向业务后台上传结果 |

LocalConverter 不维护第二套业务设备数据库；活动会话及连接状态保存在内存中。服务重启后不自动恢复无人使用的连接，页面重新申请会话。当前调试页需刷新后获取新本地凭证并手动重新连接。

## 2. 通信与媒体路径

```text
Java 后台 ──HTTP/HTTPS：设备配置和权限──→ 浏览器
                                             │
                                  HTTP/HTTPS：会话控制、截图
                                             ↓
摄像头 ──RTSP──→ LocalConverter ──WebRTC──→ 浏览器预览
                                             │
                                    HTTP/HTTPS：图片和标注
                                             ↓
                                         Java 后台
```

- 本机采集服务默认地址：`http://127.0.0.1:18090`。这里的本机是浏览器所在电脑。
- HTTP 接口负责控制和返回截图，WebRTC 作为实时预览的拟采用方案。
- 拟使用 MediaMTX 提供 RTSP 接入和浏览器预览，FFmpeg 负责截图及必要的转码；不自行实现媒体协议栈。
- 能兼容浏览器编码时优先转发，只有必要时才转码。媒体工具的版本、编码兼容性和部署参数需在单路原型中验证。
- 浏览器不得通过 Java 业务后台中转持续预览视频。Java 后台仍负责业务数据存储。

## 3. 简化代码结构

```text
cmd/localconverter/main.go   读取配置、组装模块、启动和关闭服务
internal/config/            配置读取与校验
internal/api/               路由、请求校验、响应、认证及来源限制
internal/camera/            会话、共享连接、媒体工具调用与资源回收
configs/                    示例配置，不包含真实摄像头凭据
docs/                       设计与接口说明
```

初期保持三个内部模块；`api` 调用 `camera`，不直接启动媒体进程。媒体适配代码先放在 `camera` 中，复杂度增长后再拆分。测试使用相邻的 `*_test.go` 文件。

## 4. 服务与摄像头的生命周期

### 服务程序

部署阶段配置为随电脑启动的后台进程；当前骨架仍需手动启动。关闭浏览器不会停止服务程序。退出服务时停止接收新请求，关闭会话并回收本服务拥有的媒体资源，不能按进程名称批量终止其他软件。

### 摄像头连接

1. 服务启动时没有活动摄像头连接。
2. 浏览器从后台获取当前工位设备列表及配置。
3. 用户选择摄像头，页面传入设备 ID、配置版本、RTSP 地址和访问凭证，申请会话。
4. 首次使用时建立连接；相同设备、相同有效配置已有连接时复用。
5. 每个页面拥有独立会话；页面发送心跳续租。
6. 页面切换或离开时主动释放会话。异常关闭、网络中断等情况由心跳超时兜底。
7. 同一摄像头没有有效会话后，经过短暂空闲期关闭底层连接。

设备、配置与会话的区分：

| 标识 | 用途 |
| --- | --- |
| `device_id` | 后台设备的稳定标识 |
| `config_version` | 标识连接地址等配置是否发生变化 |
| `session_id` | 标识某个页面本次使用；随机生成，并绑定调用者权限 |

连接状态拟为：`connecting → ready → reconnecting / failed → closing → closed`。会话是否有效与连接是否在线分开管理；设备断线不等于用户已经离开。

## 5. 中途变更

| 场景 | 行为 |
| --- | --- |
| 新增设备 | 页面更新列表；首次选用时传入配置，无需重启本地服务 |
| 修改地址 | 以后台确认的配置版本为准，旧会话失效并提示页面重建；不允许迟到的旧请求把配置覆盖回去 |
| 停用、删除、移出工位 | 页面发现变化后主动释放相关会话；续租授权也应限制过期配置继续使用 |
| 摄像头离线 | 仅在存在有效会话时进行有限次数重试，采用退避；失败后返回明确状态，可手动重试 |
| 页面异常退出 | 心跳到期释放会话，引用数归零后关闭连接 |
| 服务重启 | 旧会话失效，页面检查服务恢复后重新获取配置、申请会话 |

第一版页面定期刷新设备列表，间隔作为可配置参数。轮询存在发现延迟，不能宣称停用后立即断开。若需要即时撤销，需增加后台通知或本地服务主动校验机制。

后台现有设备版本是否能完整覆盖规格停用、工位变更等授权变化，需要联调确认；不能默认所有变化都会递增同一个字段。

## 6. 拟定接口

下列会话接口已经实现；完整请求、错误码和 WebRTC 信令接口见 api.md。设备级业务授权仍待实现。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 检查 HTTP 服务，不代表摄像头或媒体工具可用 |
| POST | `/sessions` | 校验配置和权限，创建会话，返回会话 ID、状态和预览连接信息 |
| GET | `/sessions/{id}` | 查询连接状态和错误原因，不返回摄像头密码 |
| POST | `/sessions/{id}/heartbeat` | 校验会话及授权，续租并返回到期信息 |
| POST | `/sessions/{id}/snapshot` | 返回有效会话对应摄像头的 JPEG 截图 |
| DELETE | `/sessions/{id}` | 幂等释放当前会话，不影响其他使用者 |

申请会话的业务字段示意（访问凭证通过请求头携带）：

```json
{
  "device_id": "camera-A",
  "config_version": 3,
  "rtsp_url": "rtsp://192.168.1.101:554/live"
}
```

预览地址或信令信息以服务返回值为准，页面不自行拼接内部媒体路径。WebRTC 信令接口与临时访问凭证在媒体工具验证后补充。

## 7. 负载控制

- 第一版标注页一次只预览当前选中的摄像头；多个页面可同时使用。
- 同设备、同配置复用底层拉流，截图尽量从已有媒体源取帧，避免重复连接摄像头。
- 限制活动摄像头数、会话数、并行截图数及转码进程数；达到上限时明确拒绝，不无限排队。
- 截图、打开连接、重连均有超时；队列必须有界。
- 优先子码流预览；高清截图如需主码流，应明确新增连接和计算成本。
- 心跳间隔、租约时长、空闲关闭延迟等值通过实测确定；建议原型从 10 秒心跳、30 秒租约、5 秒空闲延迟开始验证，而非视为最终承诺。
- 评估负载时记录摄像头数量、分辨率、帧率、编码、是否转码、CPU、内存、带宽和截图耗时，不按语言直接推算容量。

## 8. 浏览器接入与授权

本机监听不等于任何网页都可以调用。正式接入前必须限制允许的页面来源，校验请求和媒体访问凭证，会话操作绑定调用者。CORS 不能替代认证。

浏览器传入的设备 ID、地址及版本不能作为可信授权依据。建议由业务后台签发短期采集凭证，绑定设备、配置版本及连接配置摘要，本地服务验证后才连接；具体签名、密钥配置和续租方案需要与 Java 后台一并设计。配置变更后不能无限续租旧凭证。

HTTPS 页面、本地网络访问权限、HTTP 本地服务的浏览器兼容性需进行实际验证；不能仅靠允许跨域解决。局域网远程访问需单独配置监听地址及访问控制，默认不开放所有网卡。

## 9. 配置、日志和凭据

- 本地配置包括监听地址、媒体工具路径、并发限制、超时及允许的来源。
- 业务 RTSP 地址保存在 Java 后台数据库；本服务按请求在内存中使用，不额外落盘设备清单。
- 日志统一写入 `D:\projects\logs`，文件名使用 `localconverter-用途-时间戳.log`；标准错误同样放在该目录。
- 日志不得记录完整认证地址、密码或访问令牌。返回错误也需过滤媒体工具可能输出的认证信息。
- 构建产物放 `bin`，构建缓存放 `.cache`；两者不提交 Git。媒体工具按明确版本随部署包提供，不假设用户电脑已经安装。

1. 已完成：Go 分模块工程、JSON 配置读取及校验、统一日志、服务启动和健康检查。
2. 已完成单路原型：媒体依赖检查、真实 RTSP 预览、截图、停止及资源回收。

4. 接入业务：权限凭证、浏览器来源及 HTTPS 验证、前端预览和标注上传。

核心验收：多个摄像头互不串图；关闭一个页面不影响其他会话；异常退出后资源可回收；新增和变更配置无需重启；过期或无权限请求不能继续采集；服务重启后页面可重新连接。

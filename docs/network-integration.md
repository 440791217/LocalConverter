# 业务网页网络配置（开发阶段）

前端菜单：系统配置 → 网络配置。

- 采集服务默认 `http://localhost:18090`，独立于 Java 地址。
- 地址存放在当前网站的浏览器 localStorage；访问凭证仅放 sessionStorage，不进入 Java 数据库。
- 摄像头 RTSP 配置仍由现有 Java 数据库存储，本页面不改变摄像头配置。
- 开发时打开采集服务 `/debug`，复制开发联调访问凭证，在网络配置页填写，再测试连接。
- 开发默认凭证固定为 `88888888`，由配置文件 `access_token` 设置，重启不变；显式配置为空字符串时才随机生成。测试调用带 Bearer 的 `/tools`，同时检查媒体工具，不只检查健康接口。
- 测试使用页面当前填写的值；点击保存后其他采集模块才会使用新配置。

服务配置 `allowed_origins` 精确列出允许的网站来源，默认 localhost:9527 和 127.0.0.1:9527，均为 HTTP。不要填写通配符。浏览器业务登录凭证不会发送到采集服务。跨域不开放调试页面、静态资源或关闭服务接口。

标注页面已经切换到独立采集服务。Java 的 `GET /resource/device/{id}/capture-config` 校验摄像头使用权限，返回设备 ID、配置版本和完整 RTSP 地址，响应禁止缓存，不启动 Java FFmpeg。前端交给 Go 创建会话，使用 WebRTC 预览、Go 快照接口拍照，再通过原有上传流程加入步骤。每次心跳完成后间隔 10 秒续约；关闭窗口、切换摄像头、拍照完成及页面卸载时释放会话；迟到的创建结果也会释放。截图上传失败保留照片以便重试。

当前凭证是整个开发实例的访问凭证，不是用户/设备权限票据，不适合直接开放给多用户服务器。正式服务器部署仍需加入用户授权、会话隔离及 WebRTC 对外网络配置；当前服务与媒体监听保持本机地址。设备管理里的旧 Java 连接测试接口暂时保留，不影响 SOP 标注页的新采集链路。

前端随项目携带 MediaMTX v1.21.2 官方 WHEP reader（`public/vendor/mediamtx`，附许可证），不从采集服务动态下载脚本。与调试页一样，资源 PATCH/DELETE 请求携带访问凭证。将来本地模式还要根据浏览器要求适配本地网络权限。

内部 WHEP 代理在校验网页来源和 Bearer 后，移除 `Origin` 及 `Sec-Fetch-Site`，并替换为内部 Basic 凭证。两者必须一致处理：只移除 Origin 会使 MediaMTX 将浏览器的 same-site/cross-site POST 判为未授权并返回 403。回归测试同时覆盖可信来源成功、非可信来源在网关被拒绝。实际从 localhost:9527 到 localhost:18090 的浏览器预览已验证解码成功（2560×1440）。

## H.265 摄像头兼容预览

浏览器对 H.265 的 WebRTC 支持不一致，单个浏览器能播放并不代表其他浏览器兼容。服务读取 MediaMTX 的实际轨道信息：H.265 自动增加一个共享 FFmpeg 进程，将已拉取的内部 RTSP 转成 H.264 baseline 预览。浏览器不再依赖 H.265 支持。

- 每个摄像头连接只启动一个转换进程，多会话共享；H.264 输入保持直通。
- 兼容预览最长宽度 1280 像素、15fps、两条编码线程、无音频，降低 CPU 使用；输入解码也限制线程数。
- 原始拉流和高分辨率照片保留；快照仍从原始路径读取，标注使用原图。
- 最后一个会话释放后，按空闲回收规则停止转换并删除内部预览路径；进程异常退出会重试，服务退出会清理子进程。
- 转换日志统一位于 `D:/projects/logs/localconverter-preview-*.log`，隐藏 RTSP 凭据。
- 内部发布权限仅对服务生成的本机凭证开放，媒体监听仍限回环地址，网页不能直接发布媒体。

真实媒体集成测试覆盖 H.264 直通、H.265→H.264、原图快照、多会话共享及释放。

# 本机部署与排查

## 启动

1. 安装 Go SDK，在工程根目录运行 `scripts/install_media.ps1`。当前电脑的工具已安装在 `tools`；没有修改系统 PATH。
2. 运行 `scripts/start.ps1`，或 `go run ./cmd/localconverter -config configs/localconverter.example.json`。
3. 访问 `http://127.0.0.1:18090/debug`，输入设备 ID、配置版本及 RTSP 地址。
4. 点击连接，确认实际预览后拍照；关闭按钮释放会话。
5. Ctrl+C 停止整个服务，或使用 `scripts/stop.ps1` 进行正常关闭。

尚未配置开机启动，也没有改动 Java 后台和现有 SOP 标注页。首次连接才启动服务所属的 MediaMTX；无人使用时关闭摄像头源，媒体服务可以空闲待命。

## 端口

| 配置 | 默认监听 | 用途 |
| --- | --- | --- |
| listen | 127.0.0.1:18090 | 调试页、控制接口、WHEP 同源代理 |
| media.api_address | 127.0.0.1:19997 | MediaMTX 内部控制 API |
| media.rtsp_address | 127.0.0.1:18554 | 本机源复用和截图读取 |
| media.webrtc_address | 127.0.0.1:18889 | 内部 WebRTC 信令 |
| media.ice_address | 127.0.0.1:18189（UDP） | 浏览器媒体传输 |

所有监听均限制为回环地址。单独覆盖 `-listen` 不会改变其他端口，两个实例并行测试必须为每个媒体端口也分配不同值。

MediaMTX 内部使用每次启动随机生成的凭证，RTSP 地址通过 API 提交，不写入媒体配置。内部配置在 `.cache/media` 中，退出时清理所属配置。Windows 使用 Job Object 保护子进程，正常停止及强制结束父进程时只回收所属媒体进程。不要使用按名称结束所有 FFmpeg/MediaMTX 的命令。

## 日志与工具缺失

日志统一在 `D:\projects\logs`：

- `localconverter-runtime-*`：Go 服务运行日志。
- `localconverter-mediamtx-*`：经过认证地址脱敏的媒体日志。
- 安装、构建或测试需落盘的输出也写到该目录。

`/health` 成功只表示 HTTP 服务可用。调试页的工具状态会分别检查两个可执行文件。缺失时运行安装脚本，或将配置中的路径改为实际路径；相对路径以工程根目录为工作目录解释。

## 常见故障

- **拒绝连接**：检查服务是否启动、控制端口是否正确。
- **媒体启动失败或端口占用**：查看所属 MediaMTX 日志，正常停止旧实例后再启动，不要重复开多个使用相同端口的实例。
- **摄像头连接超时**：确认运行本地服务的电脑可访问摄像头，核对 RTSP 通道、端口和认证信息。
- **已连接但浏览器无画面**：优先使用兼容的 H264 码流；H265、B 帧、音频编码等需结合浏览器验证。本阶段不会自动转码所有视频。
- **截图失败**：查看 Go 日志里的脱敏原因；截图使用同一媒体源，最大 5 MiB，适当选择分辨率或子码流。
- **配置冲突 409**：先关闭旧会话、更新配置版本，再打开；仍有其他页面使用时不能静默替换旧源。
- **停用设备没有立刻断流**：本阶段未对接后台授权或变更通知，只具备本机会话租约，不能作为业务停用的即时执行机制。

正式接入业务前端还需要 Java 后台签发设备级授权、来源白名单、HTTPS/浏览器本地网络权限适配。这些边界没有通过开放 CORS 通配或关闭浏览器安全设置来绕过。
